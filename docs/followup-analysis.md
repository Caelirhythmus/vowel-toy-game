# 元音演变实验室 · 后续跟进全量分析

> 基线：当前版本（commit `e12841d`）已具备三种题型（类型 / 频率 / 系统预测）、二维 IPA 元音图、9 条声明式演变规则（带真实实例与频率档）、环境条件（重音 / 邻接元音 / 长短）、中英双语、a11y、Node 冒烟测试、GitHub Pages 部署与 README。
> 本文从**语音学（内容与教学）**与**技术（工程与产品）**两个维度，全量梳理可做的后续跟进，并按投入产出给出路线图与“不做清单”。

## 一、语音学 / 内容层跟进

### 1.1 规则库扩展

当前 7 类 9 条规则覆盖了最核心的演变方向，可扩展的方向（每条都需要真实语料 + 频率档 + 环境条件）：

| 方向 | 示例 | 教学价值 |
|---|---|---|
| 圆唇化 / 展唇化 | u→y（i-umlaut 已有，可拆出独立规则）、i→ɨ | 补全“圆唇”维度 |
| 鼻化 | VN → Ṽ（法语、汉语方言） | 展示“辅音环境触发元音变化” |
| 松紧（ATR） | 非洲语言 i/e、u/o 交替 | 扩展特征维度 |
| 长化 / 短化 | 补音长化（lengthening）、元音脱落（a→ə→∅） | 与长短特征联动 |
| 声调化 / 去声调化 | 韵尾丢失→声调产生（汉语、东南亚语言） | 跨向声调音系 |
| 弱化链 | 非重读 a→ə→∅ | 已有 reduce 的深水区 |
| 元音和谐（共时） | 土耳其语、芬兰语 | 从“演变”走向“系统” |

**注意权衡**：类型按钮从 7 个加到 10+ 个会显著抬高辨识难度。建议按难度分组（入门只见 4-5 类，进阶全量），而不是平铺。

### 1.2 音系系统级玩法（当前单规则预测 → 链移与系统重构）

这是语音学上最值得做的一层，也是现有“系统预测题”的自然延伸：

- **推链 / 拉链（push / drag chain）**：给一个元音系统，玩家预测整条链式反应（如简化版 GVS：iː→aɪ 后，eː→iː、ɛː→eː…）。可做成“逐步推进”动画题。
- **合并 / 分裂（merger / split）**：判断两个音是否合并（如 FOOT–STRUT、TRAP–BATH），以及合并对词表的影响（同音词产生）。
- **条件音变矩阵**：一条规则 + 多个环境（_#、_C、重读后），玩家勾选适用环境——直接训练“规则音变的条件性”。
- **词汇扩散（lexical diffusion）**：音变不是瞬间覆盖全部词，而是逐词扩散、受词频影响（[Phillips《Word frequency and lexical diffusion》](https://catdir.loc.gov/catdir/enhancements/fy0642/2006040171-d.html)；规律性假说并不完全成立，[Essentials of Linguistics §14.3](https://socialsci.libretexts.org/Bookshelves/Linguistics/Essentials_of_Linguistics_2e_(Anderson_et_al.)/14%3A_Historical_Linguistics/14.03%3A_Phonological_change)）。可设计“例外词”题型：大部分词变了、少数词没变，玩家找出例外——与现有“系统预测”互补。

### 1.3 真实语料驱动

- 建立“音变档案”库：从文献/百科提取真实词对（GVS 的 foot/feet、i-umlaut 的 Gast/Gäste、a-mutation 的 word 等），每道题可溯源。
- 汉语方言角度：普通话/吴语/粤语/晋语的高元音复化、元音高化链（如时秀娟《汉语方言的元音格局》）、苏北方言蟹止摄高化等，可作为中文用户的“身边案例”。
- 数据格式上把语料与代码分离（见 2.2），便于扩充、审校与署名。

### 1.4 教育法升级

- **错题重练模式**：当前错题只进结算回顾；可加“错题本单独入口”，按错误类型聚合重练（间隔重复的简化版，SM-2 太重、可只做“最近 N 天错题优先”）。
- **自适应难度**：按正确率动态调整规则池 / 题型权重 / 环境复杂度（数据已支持，只差权重算法）。
- **关卡路径**：入门（高化 + 弱化 + 频率三档）→ 进阶（全规则 + 环境）→ 挑战（系统预测 / 链移）。
- **知识卡聚合**：答题后除了当前规则，再展示“同类演变”聚合卡（如所有高化实例一览）。
- **产出型题目**：目前全是选择/勾选；可加“填空型”——给规则和源词，玩家写出结果音（输入框 + 容错匹配）。

### 1.5 多模态与音频

- **发音示范**：三种方案对比：

  | 方案 | 离线 | 音质 | 成本 |
  |---|---|---|---|
  | 预录音频（.webm/.ogg 小文件，TTS 生成或人工录制一次） | ✅ | 最可控 | 需生成/维护资源 |
  | espeak-ng WebAssembly（如 [espeak-phonemes](https://codeberg.org/jocelyn-stericker/espeak-phonemes)） | ✅ | 机械音 | 约 1-2MB wasm |
  | Web Speech API（SpeechSynthesis） | ❌ | 引擎不一，IPA 符号朗读不可靠 | 零资源 |

  建议路径：先 SpeechSynthesis 兜底 + 核心示例词预录，进阶再上 espeak wasm。
- **声学可视化**：F1×F2 共振峰散点图与舌位图并置——把“开口度≠元音全部音质”这一课讲透（呼应研究文档 §1.1）。
- **对比播放**：A、B 连播 + 波形/频谱（若引入录音）。

### 1.6 严谨性与引用体系

- 频率档（典型/偶见/罕见）目前是手工粗略估计；可升级为可追溯：标注依据（类型学文献、[PHOIBLE](https://en.wikipedia.org/wiki/Phoible) / WALS 条目）。
- 每条规则与示例附来源（词条链接、论文页码），生成《参考文献》面板。
- 学术免责声明 + “开放审校”说明（欢迎提交语料更正）。

### 1.7 概念外延（可选新模块）

- **共时交替 vs 历时音变**：ablaut（sing/sang/sung）与 umlaut 交替题型——把“A→B 箭头”的时间层次讲清楚（呼应研究文档 §1.3）。
- **比较法 / 内部重建小游戏**：给一组亲属语言词表，玩家重建原始形式——历史语言学的核心方法，天然适合做成题。
- **语流音变**：连读、弱读（a→ə 的“现场版”）。

## 二、技术层跟进

### 2.1 工程基础

| 路线 | 收益 | 代价 |
|---|---|---|
| **A. 保持零构建**（现状 + 渐进改良） | file:// 双击即用、部署最简单 | 无类型、无打包优化 |
| **B. ESM + Vite + TypeScript** | 规则表有类型约束、tree-shaking、热更新 | 本地需起服务器，部署加 build 步骤 |
| **C. 中间态：ESM 化但不打包**（现代浏览器直接 import） | 模块化、保留 Pages 直传 | 放弃 file:// 兼容 |

建议：若目标是教学模板/可移植，走 **A**；若要做成长期产品，走 **B**。迁移 B 时 `deploy.yml` 需加 `build` 步骤并改上传 `dist/`。

### 2.2 数据与配置化

- 内容搬进独立数据文件：`content/rules.json`、`content/vowels.json`、`content/corpus.json`、`i18n/*.json`。
- 加 **schema 校验**（现有冒烟测试已有雏形，可升级为 JSON Schema + 生成时校验）。
- **题库编辑器**（本地工具脚本或小页面）：可视化调整规则、权重、示例、频率档——内容与代码解耦后，非技术协作者也能扩充。

### 2.3 状态与可测试性

- 状态机形式化：当前 `idle → playing → answered → over` 已接近纯函数；可抽出**转移表**并可视化（或引 XState，但对本项目偏重）。
- 时间注入已做（`now` 参数）；下一步：**多实例**支持（同页两局对比）与**可回放**（事件日志 → 复盘）。
- 测试矩阵扩展：
  - `vitest` + `jsdom`：UI 渲染测试（当前只有 core/state 纯逻辑测试）
  - 属性测试（`fast-check`）：生成器不变量随机化验证
  - **Playwright e2e**：加载 → 答题 → 结算 → 弹窗关闭的全流程冒烟（当前最大的测试盲区是浏览器内运行）

### 2.4 CI 与部署

- PR 触发 `lint + test` 步骤（当前只有 Pages 部署）。
- 部署加 `build`（若走 2.1-B）与 `.nojekyll`（已通过 `include-hidden-files: true` 保底）。
- Pages 部署预览：PR 环境（`actions/deploy-pages` 支持预览部署）。

### 2.5 可视化进阶

- **音变动画**：SVG 中 A→B 路径动画（当前静态箭头）；链移“逐步推进”动画（配合 1.2）。
- 共振峰散点（配合音频，见 1.5）；IPA 图缩放/悬停提示（特征值 tooltip）。
- 词表变化“diff 视图”：系统题中逐词高亮变化位置。

### 2.6 游戏化与留存

- 计分体系：按难度给分、连击加成、每日挑战（“今日音变”固定题）。
- 成就徽章（如“连续 20 题无错”“见过全部 9 条规则”）、学习时长统计。
- 错题报告导出（文本/剪贴板/图片）。

### 2.7 隐私与分析

- 保持无账号、无服务器收集；本地统计（localStorage）即可满足“学习分析”需求。
- 若想要访问量统计，用自托管轻量方案（Plausible / Umami 单文件），不引第三方追踪。

### 2.8 性能、字体与可访问性深化

- **字体**：自托管 IPA 子集字体（woff2，约几十 KB），消除系统字体渲染差异（当前已做 CSS 回退，但跨平台仍不一致）。
- **性能**：当前无外部依赖已很轻；可把 chart 渲染改为答题时才构建、加 `content-visibility`。
- **a11y 深化**：
  - IPA 符号对读屏不可读 → 为每个元音/词提供 `aria-label` 的语音拼写（如 “epsilon”）
  - 选项组 `role="radiogroup"`/`aria-pressed` 语义化
  - 动画遵循 `prefers-reduced-motion`（已做基础版，动画引入后需复查）
- **多语言**：界面词条已是字典结构，可插件化扩展 fr/ja 等；内容本身的语言标注（每条实例的原语 + 译语）。

## 三、路线图建议（按投入产出排序）

### P0 —— 2-3 个小迭代，收益最高
1. **错题重练模式**（含间隔重复简化版）：数据结构现成，纯前端增量
2. **内容 JSON 化 + schema 校验**：为一切后续扩展打底
3. **音变动画**（A→B 路径动画；链移动画可后置）
4. **CI 加 lint + test 步骤**；Playwright 全流程冒烟

### P1 —— 内容与玩法主力
5. **链移 / 合并分裂系统玩法**（1.2，语音学价值最高）
6. **音频**：先 SpeechSynthesis 兜底 + 核心词预录，再评估 espeak wasm
7. **词汇扩散 / 例外词模式**
8. **TypeScript / ESM 迁移**（若接受本地服务器开发）

### P2 —— 长期与外围
9. 真实语料档案库（带引用与频率依据，1.3 + 1.6）
10. 比较法 / 内部重建模块（1.7）
11. 学习分析本地仪表盘（2.7）
12. 多语言界面与内容本地化（2.8）

## 四、“不做清单”（防 Scope 膨胀）

- ❌ 后端 / 账号 / 排行榜：无多人需求时保持纯静态
- ❌ 过度真实的音系仿真：教学简化是本项目的定位，不是缺陷
- ❌ 发音评测（打分纠音）：技术成本高、对教学核心价值低
- ❌ 为“全”而加规则：规则数量以可玩性与认知负荷为上限（见 1.1 权衡）

## 五、风险与权衡备忘

| 权衡 | 说明 |
|---|---|
| 内容扩展 vs 认知负荷 | 每加一类规则都要评估选项数、区分度、入门门槛 |
| 语音学严谨 vs 可玩性 | 频率档是“粗略估计”而非数据，需在严谨性投入与游戏流畅间取平衡 |
| 技术现代化 vs 打开即用 | ESM/TS 收益明显，但牺牲 file:// 兼容与零构建便利，需明确目标用户 |
| 音频增强 vs 资源成本 | 预录音频最可控但最贵；wasm 方案性价比高、音质机械 |
